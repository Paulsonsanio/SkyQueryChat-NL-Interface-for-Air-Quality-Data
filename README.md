# 🛰️ SkyQueryChat — plain-English questions about India satellite NO₂ data

This project converts plain-English questions into queries against a gridded NO₂ dataset and returns
the value/trend with every number independently re-checked against the raw grid.

**Deliverables → where they are**

| Assignment requirement | Where |
|---|---|
| Working demo | `streamlit run app.py` (web) or `python cli.py` (terminal) |
| Example Q&A | `outputs/example_qa.md` (19 questions, regenerated by `python run_demo.py`) |
| Validated against raw data | `outputs/validation_report.csv` (845 engine-vs-raw checks) + "✅ Verified" line in every answer |
| Real India dataset: NASA GES DISC OMI/Aura OMNO2d | `scripts/fetch_real_data.py` builds the India-region cube; `scripts/make_sample_data.py` creates a clearly labelled **synthetic** offline demo |

> ⚠️ **Honest data note.** If `data/no2_grid.npz` is unavailable, the app uses
> `data/tempo_no2_grid.npz`, which contains **synthetic** India-shaped demo data. The UI and CLI show
> "Demo synthetic data" and answers are stamped as demo data.

## 1. Quick start (Windows / macOS / Linux, Python 3.10+)

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                         # core needs only numpy
python run_demo.py                                      # offline: Q&A + validation evidence → outputs/
python -m unittest discover -s tests -v                 # 15 tests, no API key needed
streamlit run app.py                                    # web chat
python cli.py                                           # or terminal chat
```

Set `GROQ_API_KEY` and `SKYQUERY_MODEL` in `.env` to enable the default Groq planner. It tests a sample plan at
startup; after two failures it falls back to the offline rule planner.

## 2. Architecture (agentic pipeline)

```
question ─► [1 PLAN] LLM → JSON query plan (tool-use / JSON schema)      ┐ falls back to RulePlanner
              │  invalid? → error fed back to LLM once (self-repair)      ┘ on any LLM failure
              ▼
        [2 VALIDATE] strict schema + gazetteer + coverage + period checks ─► clear refusal if unsupported
              ▼
        [3 QUERY]  engine reads RAW gridded NO₂: area-mean within 25 km of the city, cloud-free days only
              ▼
        [4 VERIFY] verifier.py recomputes every figure independently (pure-Python haversine/means/OLS)
              ▼
        [5 ANSWER] template composes text from verified numbers (LLM never writes a number)
```

Why this is robust ("fail-proof"):

* **The LLM only plans.** It can't state values, so it can't hallucinate them; prompt-injection text in a
  question can at most change the *plan*, which is schema-validated.
* **Every failure mode has a defined outcome:** unknown city, outside loaded coverage, unsupported
  pollutant (PM2.5/ozone/AQI), date outside data, no cloud-free pixels, empty/garbage input, LLM down → a clear
  message or the offline fallback, never a stack trace or an invented number (see Q13–Q19 in the demo).
* **Verification is independent code**, and a test proves it catches a tampered result.
* Clouds are handled honestly: each answer says how many days had usable data.

Intents supported: `current` (latest/one-day value), `average`, `trend`, `compare`, `rank`, `peak`, `out_of_domain`.
Pollutant: tropospheric **NO₂** (units molecules/cm²). Plain-English bands (low/moderate/elevated/high) are a
heuristic for readability, **not** an official AQI.

## 4. Using real India OMI/Aura data

```bash
pip install earthaccess h5py
```

Put your Earthdata Login token in `EARTHDATA_TOKEN` in the project `.env`. NASA's public catalogue currently
lists OMNO2d observations through 2026-11-13; on fetch, the script selects the latest 120 available days.
The token is required to download the data; do not share or commit `.env`.

```bash
python scripts/fetch_real_data.py
python run_demo.py
```

The fetcher reads `ColumnAmountNO2TropCloudScreened` (molecules/cm²), crops the 0.25° grid to the India bounding
box, and writes `data/no2_grid.npz`. Missing/fill/cloud-screened pixels are NaN. It prints the actual date range
and count of valid grid cells; it does not fabricate data when authentication or retrieval fails. Since the
download has 120 global daily granules, allow time and disk space for the transfer.

## 5. 3-minute demo script

1. `python run_demo.py` → show 19 PASS and the numeric validation count.
2. In the app ask: *"Is NO2 in Mumbai rising over the last 60 days?"* → open "How this answer was produced".
3. Ask *"Compare NO2 in Delhi and Bengaluru last month"*.
4. Break it on purpose: *"What is the PM2.5 in Delhi?"*, *"pollution in Atlantis"* → graceful refusals.
5. Unplug the API key / Wi-Fi → still works (fallback planner).

## 6. Limitations / extension ideas (good for the report)

* One pollutant (NO₂). Add HCHO / O₃ by adding cubes + entries in `schema.SUPPORTED_POLLUTANTS`.
* City-centred 25 km average on a 0.25° grid. Use the `cities15000` GeoNames-derived bundled coordinates for
  major Indian places; use coordinates for towns not listed.
* GeoNames `cities15000` reference: https://download.geonames.org/export/dump/readme.txt
* Add a ground-station cross-check (EPA AQS / OpenAQ) for scientific validation.
* Add a Hindi/Spanish front-end by passing the language to the planner prompt.
