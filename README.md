# SkyQueryChathttp://localhost:8501/

A natural-language interface for satellite air-quality data over India.

Ask "Is NO₂ in Mumbai rising over the last 60 days?" and get an answer
computed from a gridded satellite data cube, not guessed by a language model.

## How it works

1. **LLM planner** (Groq, openai/gpt-oss-120b) turns the question into a
   structured JSON query plan. It never sees the data and never writes numbers.
2. **Guardrails** validate the plan, resolve places through an Indian
   gazetteer, and refuse out-of-scope questions.
3. **Geospatial engine** (NumPy) selects grid cells within 25 km using the
   Haversine formula, masks cloudy pixels, and computes the statistic.
4. **Independent verifier** (pure Python) recomputes every figure from the raw
   grid; mismatches block the answer.
5. **Streamlit UI** shows the verified answer, metric cards, charts and an
   audit panel.

If the LLM API is unavailable, a rule-based planner takes over.

## Features

- Intents: current, average, trend, compare, rank, peak
- Out-of-domain refusal (no default-city guessing)
- Cloud masking, OLS trend with R², 30-day baseline
- Resistant to prompt injection
- Web UI and command-line client

## Quick start (Windows PowerShell)

    python -m venv .venv
    .\.venv\Scripts\pip install -r requirements.txt
    copy .env.example .env      # add your own GROQ_API_KEY
    .\.venv\Scripts\python -m unittest discover -s tests -v
    .\.venv\Scripts\streamlit run app.py

## Data

> The sample grid included in this repository is **synthetic**, generated by
> `scripts/make_sample_data.py` for demonstration and testing.
> It is not a real measurement of Indian air quality.
> Real data can be fetched from NASA OMI/Aura NO₂ (see `scripts/fetch_real_data.py`
> once added).

## Limitations

- Satellite column density is not ground-level concentration and is not the
  Indian AQI.
- Cloud masking leaves gaps in time series.
